# UROVO 行业研究与每日情报库

入口：管理员登录后，侧栏 **Industry research**，或访问 `/research`。这是独立研究工作区；不会写聊天记忆，也不读取用户聊天角色。未接入定时执行、WeCom 推送、MCP 写入或自动客户外联。

## 使用

1. 选择截止日期和预算（默认3元），点击“开始十四天研究”。截止日包含在内：2026-10-24 对应 10-11 至 10-24，时区 Asia/Shanghai。
2. 可关闭页面，后台继续运行。进度显示发现/核实/审核阶段、批次、缓存复用、估算费用及停止原因；“提前收尾”最多再使用两分钟，并服从总截止时间。
3. 浏览单日、七天或十四天，按主场景和标签筛选。展开日期查看每个场景是未检索、已检索无合格发现，还是已有记录。
4. 详情包含新闻事实、证据、产品资料、竞争信息、销售建议、限制、评分和修订记录。误收可填写原因后归档。
5. 导出 Markdown 仅使用已审核、未归档且未撤回/争议的简版内容。浏览范围按首次披露日期筛选，但显示记录最新版本，截止日之后的修订明确标注，首次采集不标成后续补充。

“首次披露日”不同于事件发生日、转载日和系统抓取日。相同项目实质新进展可新建并关联旧记录；追加来源、设备型号或细节更新原记录，不复制到今日。纠错保留旧版本，已撤回内容不进入默认报告。

## 独立运行与审核

`src/research` 拥有自己的 Agent 会话、工具、存储、服务和 HTTP 路由。普通聊天的运行器、五轮历史、System Prompt、WeCom 角色和三十天会话清理均不参与。

发现/批次选择专项提示词 + 研究 System 和 `resources/research/SKILL.md` 指导研究方法；`business-context.md` 是业务理解基线；`reviewer.md` 是独立审核标准，`rubric.md` 固定行业情报的评分标尺。竞争部署、同类新品与渠道生态变化可以有高情报价值；不是UROVO客户、金额未知、没有确认硬件订单不构成通用扣分理由。可在数据目录的 `research/urovo-business-context.md` 保存管理员修订版；存在时优先使用。每次运行保存完整背景及 SHA-256，运行中不变化。研究员没有改写背景的工具。

正式产品依据只读 `urovo-product-expert`、`memory`、`ums-expert` 根内的 Markdown。搜索仅发送必要公开关键词。引用必须匹配已捕获原文，产品主张必须有内部资料引用；审核员先核对后台从实际正文截取的上下文，必要时补读全文，独立核对业务关系、日期、正文、事实、产品主张及两个版本的一致性。网页里的指令不是授权。捕获正文会提取页首明确的中英文发布时间标签；归档日期与这些标签冲突时，代码拒绝候选并返回原文，防止签发/实施日混入公开日期。该检查不从URL猜日期，也不能替代对其他日期格式的独立审核。

各项0–5分：业务相关30%、商业25%、证据20%、行业重要15%、新增信息10%。默认总分≥70，相关度和证据≥3，所有硬性检查通过且没有待修正项才入库。纠错可低于商业评分门槛，但证据检查不豁免。模型仍可能误判，因此保留可追溯依据及人工归档入口。后台检查点按实际保存结果分别显示已入库、低于分数门槛、拒绝与待审核；模型的证据判断放在单独的审核备注中，不作为入库计数。

## 增量发现与预算

先由独立低推理发现员结合业务背景、既有条目、历史台账和搜索摘要，寻找新事件或重要补充；发现阶段最多总预算的20%（默认0.60元）。搜索摘要不能入库。没有明确待追查方向即结束，不要求运行满五分钟。完整补查未到期时仍轻量探测全十四天，重点追查最近检查日期附近和覆盖缺口；超过七天的场景全窗口补查在下一次人工启动时进行，不是定时任务。

每批由轻量选择员比较待处理线索（必要时查询全库）并挑选最多三条，而不是按URL返回顺序取前三条；选择也计入发现额度。然后重新建立研究上下文，按需读取正文/产品依据，然后独立审核并立即保存。批次间只传摘要、反馈及证据句柄，不重放全部网页。专项提示词与业务背景在启动时一并冻结，System及历史请求前缀保持稳定；工具 Schema/业务背景变更仍会影响缓存，供应商缓存不保证命中。模型自行选择公开检索词、来源和追查路径。

正文、日期和业务关系已通过、证据分≥3且达到总分门槛，但事实引用/归因、产品措辞或简详一致性有明确可修问题时，仅允许一次已有证据修正；修正员没有联网工具，随后仍须独立复审，失败不入库。原拒绝与修正关系保留，修正不算额外新增。候选提交连续两次结构或引用无效则暂停该批，保留线索并转向其他方向，避免反复输出同一份错误长JSON。

合格新增、重要补充和有效纠错算成果；重复来源和润色不算。连续两批无成果、无待追查方向、预算到审核预留边界或用户提前收尾时结束。默认20分钟硬上限，最后两分钟不再扩展新方向。审核每批最多60秒，已经完成的有效判定保留，未审核内容不发布。报告直接导出已保存记录，不额外调用模型。

研究员、发现员、审核员及搜索/抓取共用费用账。调用前根据实际请求UTF-8字节及模板保守上界、最大发送输出量预留，完成后按SDK实际缓存命中/未命中输入与输出结算；推理token已包含在输出，不重复计费。保留25%总额度给审核，发现预算用尽后可转入深入阶段。SDK和Provider隐式重试关闭；搜索暂时错误最多两次显式重试，每次重新预留。网页18秒、无自动重试，最多三个独立URL并行。

费用为保守估算，不能当供应商账单。缺失用量、取消和不确定网络失败保留预留；HTTP明确工具失败/空结果不计工具费。内置价格只匹配官方DeepSeek deepseek-flash，按2026-10-26高峰价：每百万输入未命中2元、命中0.04元、输出8元；搜索/抓取各0.005元，提前按已公告收费标准预留，不依赖免费活动。[官方价格](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/)。价格版本每次固定，需随供应商变更维护；其他模型/代理必须配置匹配的价格，不能按SDK零费用启动。额度不足保留线索并明确说明，不宣称没有行业新闻。

## 数据与恢复

`AGENT_DATA_DIR/research/`（默认 `.data/research/`，保持 Git 忽略）：

- `library/items/<uuid>.json`：稳定条目、版本、引用正文快照及修订历史，是正式库事实来源。
- `library/index.json`：可重建的每日/场景索引，启动时从条目恢复。
- `runs/<uuid>/run.json`：背景快照、配置、覆盖、候选、检查点、计量、停止原因；并保存最多240条去重的发现线索（标题、URL、搜索摘要、场景、优先级、已读/待追查/暂缓等状态与原因）。搜索摘要不是正文证据。
- `runs/<uuid>/audit.jsonl`：研究员与审核员的工具/响应审计日志，属于内部数据。
- `runs/<uuid>/evidence/`：本次实际读取的网页及内部资料证据。
- `ledger/state.json` 与 `ledger/evidence/`：跨次线索/查询覆盖/分类结论和可复用公开正文。旧任务首次导入，缺失状态视为未知；正文二十四小时且摘要未变才复用，重复/明确无关结论七天冷却，事实摘要或规则变化可重新打开。未核实的线索保留，不当作拒绝。台账v2补入历史日期拒绝：同版正文及同批已有转载来源不因新运行而重新获批；审核收到此前疑点，需新日期依据或明确规则修订。升级v1会重新导入相应历史，不修改正式条目。
- `runtime/`：独立 SDK 的临时目录；正常结束删除，不持久化 API Key。

每次审核逐条原子写入，操作ID防重放、版本号防覆盖；重启将未完成任务标为 interrupted，已入库条目保留，未审核候选不自动发布。再次运行同一日期范围加载既有记录，继续发现与补充。保留历史研究和库数据；不会由聊天会话清理器删除。不要把旧试跑 Markdown 直接复制成正式条目。

## 配置与部署

模型复用 `BASE_URL / MODEL_ID / API_KEY / CONTEXT_WINDOW / MAX_TOKENS`，研究使用 high 推理档，独立审核使用 low 档以控制一分钟审核时限。DeepSeek 直连时复用模型 key，其他模型供应商需配置 `DEEPSEEK_API_KEY`。研究联网能力与聊天页面的工具开关独立。

预算以人民币计，时间参数以毫秒计；未设置使用以下默认值：

```dotenv
RESEARCH_BUDGET_CNY=3
RESEARCH_MAX_MS=1200000
RESEARCH_WRAP_MS=120000
RESEARCH_REVIEW_MS=60000
RESEARCH_FETCH_TIMEOUT_MS=18000
RESEARCH_THRESHOLD=70
# 权重合计必须为100
RESEARCH_WEIGHTS={"relevance":30,"commercial":25,"evidence":20,"importance":15,"novelty":10}
```

旧RESEARCH_INITIAL_MS/CHECKPOINT_MS不再调度生产研究，改为批次边界。最大时长必须大于收尾时间；审核上限不能超过收尾时间。配置在任务开始时固定。参数变化不要求迁移既有条目。

交付代码及 `resources/research`、`resources/web/research.*` 后执行 `npm ci`、`npm run build`，按现有部署方式重启 Web/Agent 服务即可。该功能不需要改动或构建 WeCom Bridge。本次开发不会自动重启 VPS。现有本机验证完成并由管理员提交/推送后，VPS更新步骤为：

```bash
git pull --ff-only
npm run build
sudo systemctl restart product-expert.service
```

无需重启`wecom-bridge.service`。部署前按既有方式备份 `.data`；研究库属于长期业务数据，也要纳入后续备份。一个数据目录只启动一个 Web 进程；多个副本共享文件目录不属于首版支持范围。

## API 与验证

所有接口沿用管理员 Cookie、Host/Origin 和写操作 CSRF 校验。WeCom/MCP 凭据不能访问。

- `GET/POST /api/research/runs`：运行列表／启动，启动体 `{endDate, budgetCny?}`，预算范围0.05–100元；省略沿用默认值。状态返回阶段、批次、预算/预留/缓存token统计、实际新增/补充与复用计数；旧任务费用显示未知。
- `GET /api/research/runs/:id`，`POST /api/research/runs/:id/stop`。
- `GET /api/research/items?endDate=YYYY-MM-DD&days=1|7|14&scene=...&tag=...`：条目及每天的覆盖。
- `GET /api/research/items/:id`，`POST /api/research/items/:id/archive`（`{reason}`）。
- `GET /api/research/export?endDate=YYYY-MM-DD&days=1|7|14`。

同窗口业务验收：使用空隔离库开展盲搜，不把旧试刊的标题/URL作为任务输入；结束后对照试刊逐条说明发现、追查、入库与遗漏情况，另核对实际新闻与销售建议。通过自动化不代表研究质量已经验收。

本机：`npm run typecheck`、`npm test`；研究定向测试：`npm run build && node --test tests/research*.test.mjs`。

真实模型：`node scripts/validate-research.mjs --real --passes=3 --budget=3 --seed-library=<既有已审核验证库items目录>`。三轮分别从空库、部分补入、完整补入已审核样本继续检索；已有样本只用于重复/增量判断，不是新闻已穷尽的证明。无seed默认同窗口连续两轮，支持passes=1/2/3。结果在隔离validation目录，不修改正式库；全部校准/试跑/失败/重试通过固定`research/validation-budget-adaptive-v1.json`合计9元封顶，重启和新建验证目录不重置。再次授权扩大验证前不得删除或重置该账。`--real`仍是必需开关。实际验证结果和局限见dev-history。

自定义价格通过`RESEARCH_PRICING_JSON`提供（字段见`.env.example`），必须与请求modelId/baseUrl精确匹配，金额为CNY、模型按百万token、工具按次；价格须大于零并注明版本与依据。内置峰值价格也可能高于真实账单；价格突然上调等外部变化需要维护配置，代码无法提供供应商侧消费限额保证。
