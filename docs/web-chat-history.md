# Web 对话历史分页

打开已有对话时，Web 只请求最新 30 条可见消息，直接定位底部。聊天区域不对历史消息使用入场动画或平滑滚动；切换对话不刷新或等待侧边栏列表。向上距离顶部不足 300px 时自动加载上一批，也可点击顶部的加载按钮。

插入更早的消息后，保持当前可见消息的位置。旧消息不重复解析 Markdown，已展开的工具详情在消息内容未变化时保留。加载失败可重试；游标失效时提示重新打开对话。快速切换、新建空白对话或发送问题会取消不再需要的历史请求；旧响应不能覆盖当前对话。首次加载失败不会保留上一段对话正文，也不能向未成功加载的会话发送问题或上传附件。

## API 与兼容

- `GET /api/sessions/:id/history?limit=30&before=<cursor>`：Web 登录保护，默认 30 条，`limit` 为 1–100 的整数。`before` 是绑定会话和稳定消息位置的不透明游标。
- 返回 `messages`（每条包含稳定 `id`，按时间正序）、`page: {hasMore,nextCursor}`、`rounds`、`contextRounds`、标题、运行状态、最新五条运行记录和附件元数据。不是附件文件本体；工具详情仍通过原展开接口请求。
- 游标随消息追加和普通服务重启保持有效；格式错误或跨会话游标返回 400，位置已不存在返回 409。不会把无效游标当作第一页静默返回。
- `POST /api/sessions/:id/run` 可传 `historyPageSize: 30`，使 SSE `done` 返回最新一页及分页状态。Web 按 ID 合并已有消息；若单次运行新增超过一页，会补取连接段，避免保留旧历史时漏掉中间消息。
- 原 `GET /api/sessions/:id` 和未传 `historyPageSize` 的运行请求仍返回原有完整消息格式；企微 API 不新增历史分页入口。

历史记录、保留时间、模型上下文和文件下载行为不变。分页只影响展示；不会因为首屏只显示 30 条而减少或扩大模型的五轮上下文。没有新增环境变量、依赖或数据迁移。

## 验证和边界

`npm run build` 后运行：

```sh
node --test tests/chat-history*.test.mjs tests/chat-attachments-ui.test.mjs tests/web.test.mjs tests/web-files.test.mjs
```

测试覆盖完整分页遍历、重复时间戳、追加消息、重启、无效/跨会话游标、鉴权、附件与生成文件、工具占位回复、旧接口兼容和五轮推理上下文。UI 测试覆盖位置保持、请求取消、并发去重、失败重试、游标失效和跨多页回复合并。

本机合成的 200 轮、400 条消息：完整接口响应 452,419 字节，首屏分页响应 34,714 字节，减少约 92%。真实 Chrome 夹具验证首屏 30 条、底部距离为 0、无历史动画；向上加载后的锚点偏移约 0.3px。一次 400 条对 30 条的 Markdown/布局采样分别约 60ms 和 4ms。这些是本机合成数据，不代表生产网络、冷启动或固定响应时限。

另用真实 Chrome 连接隔离的真实本地后端和模型夹具验证：首次 30 条，上滑后 60 条，发送完成后合并为 62 条且旧 DOM 保留，刷新后重新显示最新 30 条。模型请求仍为五轮用户上下文，无浏览器脚本错误。

首版不引入浏览器历史缓存、持久化会话索引或虚拟列表。SDK 冷启动仍可能读取完整会话文件；每条消息正文保持完整，因此单条特别长的回答仍有解析成本。服务端先选定可见消息范围，再生成该页展示正文，并在同一次构建中复用工具统计。

## 上线与回退

实现验证不自动推送或部署。上线时一起更新前后端、构建并重启 `product-expert.service`，随后刷新浏览器页面；Bridge 无需升级。旧页面继续使用原完整接口。

回退代码、重新构建并重启后刷新页面即可；不需要恢复或转换聊天数据。
