# Sync 完成通知与区间消费

每次手动 Sync、Re-Sync 或实际处理文件的 Auto-sync 结束后，Bridge 主动私聊通知现有余额通知接收人，并可选向指定群发送结果摘要。无须新增定时设置、systemd timer 或工具开关。通知不调用模型。

完整私聊通知的接收人只取全局 `WECOM_NOTIFY_USER_ID`，发送机器人只取配置列表的第一个，与余额报送一致。为空时不发送，不回退到群、历史对话、其他机器人或各机器人 `notifyUserId` 覆盖值。更换机器人/接收人后不把旧待发内容发给新账号。

## 通知内容

- 结束时间（北京时间）、完成/失败/停止/中断状态。
- 简洁概览：文件总数、已入库数量；仅在非零时展示失败/中断、待处理、重复/跳过、未处理数量。
- 最多八个文件独立分段展示名称、状态及最多两条短摘要；其余到 Sync reports 查看。
- **上次实际 Sync 完成 → 本次实际 Sync 完成**区间的模型消费，以及本次 Sync 自身的模型消费。
- 对应报告 ID。

一天内多次执行时每次更新边界，不按零点切分。失败、停止或中断也生成结束记录，并推进到该次结束时间。Auto-sync 超过五十个文件分成多批时，整轮结束只发一份汇总；中间批次不重复通知。空目录、忙碌未启动或全部已处理的跳过运行不发送，也不推进统计区间。删除预览、清理重试和单独确认发布不被当作一次新的 Sync 推理执行。

首次部署不群发已有历史报告。第一次新通知以最近已有 Sync 完成时间作为区间起点；没有历史完成时间则以启用时刻建立起点。旧版报告没有逐请求计费记录，因此跨越启用前时间的区间会明确标为历史不完整。

## 通知排版

结果按“标题与北京时间 → 文件概览 → 每个文件的状态和短摘要”分段，文件名加粗，使用空行分隔，保留文件名下划线。成功、部分需处理、失败、停止和中断使用不同标题，不把整体失败或待处理说成全部成功。

每个文件最多两条摘要，每条最多 72 个字符；较长短句以省略号收尾。通知过滤包含内部路径、节点键、索引文件等实现细节的子句，以及已入库结果中规划阶段的暂存提示；只保留原摘要中可读的短句，不额外调用模型生成新事实。无法提取时显示文件状态并引导查看网页报告。网页报告原始摘要不修改，正常业务日期（如 2026/11/04）不作为路径删除。

示例：

```text
✅ 自动同步完成
2026/11/04 07:01（北京时间）

📊 共 1 个文件，已入库 1，无失败。

📄 SQ68 A13 GO修改记录.xlsx
状态：已入库

更新摘要：
- i9200 相关资料更新
- 注明 WUZL 工作表现为两行（2025-10-21、2026-11-03）

完整内容请查看网页 Sync reports。
```

个人完整版在文件摘要之后单独显示“模型消费”区域；统计区间、区间总消费、本次 Sync 消费、计价覆盖与历史不完整说明均保留。群消息仍不附费用区域。

更新后需构建并重启 Agent，新生成的通知采用新版排版。Bridge 无需改动，无新增配置。已发送或已冻结在队列中的通知不重新排版或重发，避免破坏分片投递检查点。

## 群摘要通知

可在主项目 `.env` 中设置（Agent 和 Bridge 读取同一份配置）：

```ini
WECOM_SYNC_GROUP_CHAT_ID=目标群的ChatID
# 留空使用第一个已配置机器人；多机器人时可明确指定已在目标群里的机器人。
WECOM_SYNC_GROUP_BOT_ID=
```

Chat ID 从 `/wecom-contacts` 页面目标群的独立卡片复制。不要把群 ID 填进 `WECOM_NOTIFY_USER_ID`；该项继续保留个人账号。群配置留空时关闭群通知，个人通知和余额报送不受影响。

群内仅包含结束时间、状态、文件数量、文件名和更新摘要，即完整通知的上半部分。摘要直接从同一份结束事件生成，不转发完整私聊文本，不附带消费区间、计费完整性、余额、模型用量或报告 ID。个人通知保留完整费用信息，消费区间与统计口径不变。

群通知有独立的 `.data/sync-notifications/group-state.json`、目标指纹、租约和 Bridge 分片检查点。一边离线或失败不会阻塞另一边；更换群不转发之前群的积压消息，首次启用不回放历史报告。相同事件给个人和群的 ACK 分别记录，重启不会把两边的发送进度混用。

## 费用口径

统一逐请求记录覆盖 Web/企微/MCP 对话、Sync 文本与视觉、主记忆预览、行业研究、固件条件提取、Library 分类、文件视觉识别。SDK 的 `cost=0` 不作为真实免费依据，不直接相加旧报告的 token 快照，以免缓存和重试重复计算。

金额为 **CNY 估算**，复用已有研究价格规则与适用的 `RESEARCH_PRICING_JSON`，按请求开始时适用的价格版本保存。内置规则仅适用于既有规则支持的官方 DeepSeek 模型与地址；其他提供商、视觉模型或缺少价格的请求不猜价格，而是标为未计入。缓存读、普通输入/缓存写和输出分别计算。未知 usage、未结算请求、没有适用价格和启用前历史缺口都会单独标出，不作为零消费。

这不是服务商账单或账户余额差额。区间模型消费不包含外部搜索/抓取等单独服务收费，也不包含其他项目或直接从服务商调用产生的消费。余额定时报送保持原样。

按已持久记录的请求结算时间归属，左端不包含、右端包含。跨边界尚未结算的请求在之后的区间计入；同毫秒及多进程写入通过持久化结算边界和文件锁避免遗漏。金额和区间随通知一起冻结，投递重试不会重新按当前时间计算。

## 恢复与保存

- `.data/knowledge-sync/jobs/`：保留原报告，并增加每次执行的 ID、起点、目标文件及可选自动轮次归属。
- `.data/sync-notifications/events/`：不可变的结束快照。Re-Sync 新建执行 ID，不覆盖上一次执行结果；重启恢复新版本中断报告时生成一次中断记录。
- `.data/sync-notifications/state.json`：接收目标指纹、已处理事件、上次完成边界和带租约的待发通知。
- `.data/usage-ledger/`：内部 `.accounting.lock` 统一协调 Agent 与独立导入进程；其他记录包含调用来源、模型、时间、token、适用价格和估算金额；不保存 API key、提示词、回答、附件路径或图片。
- `.data/wecom/bridge-state.json` 的 `syncDeliveries`：成功发送的文本片段进度。ACK 丢失或正常重启后不重复发送已记录部分。

文件采用权限 600，目录权限 700。通知检查点损坏时保留文件并暂停通知模块，普通聊天和 Sync 不因此停止。Bridge 离线时后台保留结果，恢复后投递；进程反复启动不重新跑 Sync。仍存在平台已接收但本地发送检查点未落盘的崩溃窗口，不承诺平台消息严格 exactly-once。

## 部署

此功能只更新主项目，和本机固件下载服务及 cloudflared 无关。管理员按原方式同步代码，待当前任务结束后执行：

```bash
cd /opt/ProductExpertCloud
npm run build
systemctl restart product-expert.service
systemctl restart wecom-bridge.service
```

继续沿用已有 `.env` 中的 `WECOM_ENABLED`、机器人凭据、`WECOM_API_TOKEN` 与余额报送使用的全局 `WECOM_NOTIFY_USER_ID`。群通知按需新增上面的两个配置项，之后同时重启 Agent 和 Bridge；无新 npm 依赖或 systemd 安装。本轮未访问或修改 VPS、未发送真实企微消息，实际主动消息权限和部署后首轮通知由管理员验收。


## 独立 Library 导入的账本权限修复

2026-11-02 修复了独立 Library 定时导入在写费用账本时出现 EROFS 的部署遗漏。该服务保持 `ProtectSystem=strict`，仅新增 `.data/usage-ledger` 的写入白名单；共享锁统一移入账本内部。升级时需先停止旧 Agent/导入进程，再构建、安装增量 drop-in 并启动，避免新旧锁位置混用。个人与群通知的格式、消费边界及余额报送不变。具体命令见 [Library 导入修复步骤](library-import.md#2026-11-02-usage-receipts-fail-with-erofs-in-the-standalone-importer)。
