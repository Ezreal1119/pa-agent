02

六个核心能力

1

产品知识问答

根据问题读取相关产品资料、专家技能和记忆，支持跨资料比较、多轮追问及资料链接查询。

知识依据来自已整理的文件与索引。

2

知识持续更新

手动上传或导入外部资料，经文档转换、产品归属与版本判断、发布校验后，更新正式知识库。

保留报告；歧义与特定覆盖操作交由管理员确认。

3

文档读取与生成

处理 PDF、Word、PPT、Excel、图片与文本附件，按已启用的工具读取内容、填写模板或生成新文件。

原件、临时处理和输出分别管理。

4

行业研究

围绕产品业务发现公开信息，保留正文证据，结合内部资料分析，经独立审核形成可追溯的情报库。

使用独立研究上下文、预算和历史记录。

5

固件分发

从用户描述提取型号、日期和版本序号，匹配候选，选包与确认后由本机服务执行传输。

专用命令进入，任务进度与完成链接回传。

6

管理与运行反馈

集中管理提示词、记忆、工具开关、联系人与群组，并查看工具记录、任务报告和模型用量。

Sync 完成通知可分别投递个人完整版与群摘要。

03

四条主要工作流程

一次知识问答用户发起
接收问题→加载技能与记忆→检索 / 工具 / 推理→回答或文件

每个会话独立保存历史。模型根据问题选择已开放的工具；同一轮可多次检索，最后交付结果并记录执行情况。

一份资料入库手动或定时触发
导入待处理区→转换与 AI 判断→后端校验 / 必要确认→发布与通知

导入和 Sync 是两个步骤。AI 提出更新方案，后端检查内容、路径、索引及版本关系，再提交正式更新；存在业务歧义时保留报告等待处理。

一次行业研究管理员发起
发现线索→读取并核实正文→独立审核→保存 / 导出条目

搜索结果作为线索，实际正文与内部资料构成依据。通过审核的条目逐条保存，研究进度和消费单独记录。

一次固件分发专用命令触发
提取条件并匹配→选择与确认→本机下载 / 上传→发布校验与交付

同一时间处理一个固件请求，按任务状态定时反馈进度。上传、资料库发布及校验全部成功后删除本机缓存；失败重试所需文件保留。

04

部署时各部分放在哪里

以一台应用服务器承载核心服务，再按需连接外部模型、资料来源和本机执行端。

APPLICATION SERVER

应用服务器

主应用进程网页与 API、MCP 接口、问答运行时、知识维护、研究与管理功能。
企微 Bridge独立进程，负责接收消息、调用主服务和投递回答、文件与通知。
定时与导入定时器触发资料导入进程或 Sync 调度；Sync 使用主服务的维护流程。
持久化目录存放正式知识、记忆、会话、附件、报告与任务状态，独立于代码管理。
OPTIONAL LOCAL WORKER

本机固件执行端

本机服务Python 服务执行固件下载、上传、校验及成功后的缓存清理。
连接方式通过 Cloudflare Tunnel 与独立凭证供主服务调用；上传按配置走代理。
状态与交付本机 SQLite 保存任务检查点；R2 保存文件并提供下载链接。服务离线时入口显示维护中。
当前技术组成：主服务为 Node.js + TypeScript，Agent 基于 Pi SDK；网页使用 HTML / CSS / JavaScript；文档处理结合转换工具与可选视觉模型；主服务以 Markdown、JSON / JSONL 与文件目录保存内容和状态。模型通过兼容接口接入，文件分发使用对象存储。
05

参考搭建的推荐顺序

第一步 · 跑通知识问答

准备模型接口、专家技能与最小知识库，先让网页完成“提问 → 检索 → 回答”。明确知识、记忆和会话历史各自的保存位置。

第二步 · 建立更新闭环

增加资料上传、文档转换、Sync 校验与报告，再接入企业微信。按需配置定时导入、自动 Sync 和完成通知。

第三步 · 扩展业务能力

逐项开放文档工具、MCP、行业研究和本机固件服务。每项分别配置权限、状态记录与结果校验，按需启用。

实现时保留的边界：管理员登录与机器调用凭证分开；普通问答、知识维护和研究使用各自的工具权限；主记忆通过管理入口维护，聊天记忆工具写额外记忆。知识文件、运行数据和凭据独立管理，配置能力开关后由后端执行约束。
