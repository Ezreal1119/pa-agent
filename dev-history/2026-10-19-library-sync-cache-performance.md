# 全缓存 Library 同步减负

## 问题与证据

VPS 一次任务 272/272 张不同图片全命中缓存、0 次新评分，但后端仍运行 163 秒；随后 0 文件更新的完整同步仍需 76 秒。该任务的 658 个图片路径约 677 MB，最终任务状态 JSON 约 20 MB，其中图片结果的压缩 JSON 约 12.8 MB。原图片循环对每张图片调用完整状态原子写盘；管理页每 1.5 秒取回完整详情并重复构建图片报告。三份摘要更新还产生约 270 条历史提示，原实现每条提示亦立即写盘。

## 调整

- 复用、预览、跳过与历史提示按 50 项或约 2 秒批量保存；真实文件写入事务与错误/冲突仍立即保存。任务结束或阶段结束会保存最后状态。
- 另存仅含计数、阶段、当前项和图片总览的小型 `progress.json`，旧 `state.json` 继续作为可恢复任务的权威数据；损坏或缺失的小副本可从权威状态读取。旧的已结束任务首次读取后补建小副本，避免每次打开历史都解析大文件。Web 轮询、最近历史使用轻量接口；完整详情由用户请求，图片报告在展开时才渲染。原完整 GET 接口兼容。
- 图片评分阶段复用当轮原始资料 Hash 快照，不再为每个图片路径重复读取并计算 Hash；首张评分输入仍核对内容。摘要阶段末再次扫描原始资料，以完整 Hash 比较发现同期修改，核对通过后才发布图片索引。没有用 mtime/文件大小代替内容校验。

本机 `npm test`：202 通过、2 跳过、0 失败；新增图片同期变化、轻量进度接口、旧任务副本回补与批量记账的测试。最后补丁后同步测试 24/24 通过；`npm run typecheck`、`npm run build`、前端 JS 语法检查及 `git diff --check` 通过。
