# 聊天输入区文件拖放与粘贴

- 文件选择器、输入区拖放和问题框文件粘贴统一调用 `uploadAttachments`，继续使用原认证二进制上传接口。附件准备好后由用户显式发送，保留文字草稿。
- 从 FileList 或剪贴板 items 读取真实文件，不重复合并同一数据。无扩展名的 PNG/JPEG/WebP 截图补可用文件名；文件夹、超限、非法格式在上传前提示。
- 拖入时高亮输入框，离开、取消、窗口失焦或开始上传后清理；输入区之外的文件拖放不会导致浏览器跳转。
- 问题框的普通文字/HTML 粘贴与其他输入框保持原生行为，不读取或请求额外剪贴板权限。系统/浏览器没有暴露的本机文件不能通过文件路径补读。
- 上传期间保留原 Stop 行为和忙碌限制；取消或后续失败保留此前成功的附件。固定上传会话 ID，并丢弃过期的会话加载响应。
- 静态资源即可部署，无后端 API、服务配置、新依赖或环境变量变化。未操作 VPS 或真实配置。

验证：JavaScript 语法检查、TypeScript 构建通过；`node --test tests/chat-attachments-ui.test.mjs tests/web-files.test.mjs` 共 23 项通过，零失败/跳过。新测试直接执行真实 app.js，覆盖三入口、截图、普通粘贴、格式/大小/数量、文件夹、禁用/忙碌、拖放反馈、取消/部分失败及会话竞争；原服务测试覆盖真实本机 HTTP 上传、附件归属、重启、配额、发送与下载。日志 `.data/chat-attachments-tests.log` 不提交。Windows/macOS 原生文件管理器剪贴板仍需在实际浏览器验收，不宣称全平台复制文件组合均已实测。
