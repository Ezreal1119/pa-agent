# Library 同步复用路径提速第一版

用户反馈全量同步时 1944 个项目均复用，仍等待较长时间。此前复用的是模型结果，但翻译项目反复校验并写检查点，摘要项目再次读取字段、计算多层 Hash，复用进度按项重复写完整任务状态。

本版只优化已证明不变的项目。译文阶段先计算的双方文件 Hash 与持久化基线相同时，直接记复用；缺失、变更、删除、首次接管仍走原事务路径。翻译结束后按内容 Hash 扫描原始资料，图片阶段使用扫描结果分组。摘要阶段对每个目标记录原始资料文件及来源布局签名，并绑定成功输出的 `summary.json` 和 `overview.json` Hash。下一轮只有输入签名和两份输出 Hash 都匹配才快速复用；否则走完整摘要路径。额外在结束前重新扫描原始资料并核对快速复用输出，避免同步期间人工上传的改动成为成功基线。代码实现变动也会使摘要签名失效。该清单保存在既有 `sync-baseline.json` 的可选字段中，旧清单无需迁移，首次运行建立新签名。

译文和摘要的快速复用进度每 50 项或 2 秒保存一次；修改文件的事务、检查点、错误和取消仍立即持久化。进程异常退出最多导致部分复用计数重查，不会丢失已提交的文件修改。模型调用、评分公式、翻译校验、原始文件、桌面端及单独摘要维护任务的既有行为不变。单次扫描需要读取相关原始文件的内容；为了检测同步期间的外部修改，摘要阶段结束前再扫描一次。修改少量文件时，只快速跳过未受影响的摘要目标；译文和图片仍保留其既有逐项验证与缓存机制。

验证命令：`npm run typecheck`、`npm run build`、`npx tsx --test --test-timeout=30000 tests/ckd-library-sync.test.ts`、`npm test`。完整测试 190 项通过、2 项因平台条件跳过、0 失败；同步专项 21 项通过。新增回归覆盖无改动时全部摘要快速复用、只改一个工序时仅受影响目标重做、相同大小且恢复修改时间的内容变更、缺失生成结果、同步途中编辑原始资料及输出文件的拒绝。临时资料库 40 个工序的受控本机测量：首次同步 12.63 秒；无改动且启用新摘要清单 0.20 秒；删掉摘要清单后走旧摘要核对路径 0.55 秒。该数字不能代表 1.6 GiB VPS 或正式资料库，不含真实模型延迟。

部署前确认 VPS 无正在运行的 Library 同步，旧版三对源文件与编译文件备份至 `/opt/pi-patrick-backups/library-sync-manifest-20261019/`。只同步三个修改文件及新的 `library-sync-snapshot` 的 TypeScript/JS 文件；VPS `npm run typecheck` 通过，重启 `ckd-sop.service` 后公网管理员入口 HTTP 200。Node 22/Linux 上用 `/tmp` 临时两工序 Library 与受控模型跑两轮同步，均完成、错误 0，第二轮四个摘要目标全部快速复用；临时数据和脚本已删除，正式 `.data` 与 Library 未跑全量同步、未调用真实模型。新签名会在正式 Library 下一次完成摘要阶段且没有摘要错误后建立；其后的无改动同步才能使用摘要快速路径。
