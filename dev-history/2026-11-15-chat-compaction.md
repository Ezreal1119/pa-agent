# 回答交付后的会话上下文整理

- 新增可选 `CHAT_COMPACTION_*` 配置，默认关闭；默认阈值 384000 token、保留五轮。开启后原文持续累积，在回答交付后检查并安排整理。
- 独立模块复用 Pi 的公开 `compact`、compaction 检查点和上下文重建。按用户消息条目 ID 切分，不拆工具链；摘要请求使用独立流及计费，不受聊天系统提示和工具注入影响。
- 单独的串行整理队列，同会话提问等待整理，普通问答槽位仍可供其他会话使用。失败保留原文、记录冷却时间；取消及删除后不能写入迟到摘要。
- 按用户选择，旧会话从当时最近五轮开始累积，持久化起点，不集中总结全部旧历史。上下文与历史展示分离，历史轮次、工具详情、附件及问题 UUID 查询保持稳定。
- Web/企微在响应结束后安排整理；HTTP API/MCP 在终态结果落盘后安排整理，延后会话销毁。上下文轮数不把 Pi 的摘要消息算成用户提问。

验证：构建、类型检查、前端语法及 `git diff --check` 通过；本地模型夹具下 82 项相关测试全部通过。覆盖阈值与缓存用量、完整五轮、重复时间戳、连续摘要、重启、旧会话迁移、超时/取消、冷却恢复、删除后不重建、同会话等待和跨会话执行、工具及附件关联、Web/企微/API/MCP 结果与独立计费。测试显式固定普通问答并发数为 4、等待容量为 8，避免开发机环境覆盖夹具默认值。

额外扩大检查时，既有文件转换测试因本机缺少 `.data/file-runtime/bin/markitdown` 未通过；既有受限进程记账测试受到 Node 26 Permission Model 禁止 `fsync` 的限制。未修改这些业务模块、依赖或运行环境。
