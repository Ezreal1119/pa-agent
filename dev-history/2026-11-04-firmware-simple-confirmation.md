# 固件直接回复确认

按用户此前明确要求，待确认阶段不再要求六位确认码。提示改为“回复‘确认’开始”，原发起人在原机器人、原会话内发送包含连续两个字“确认”的消息即可提交，例如“确认”或“好的，确认下载”。匹配是字面包含判断，不调用模型。

- 新流程不生成确认码；Bridge 校验提示同步去掉确认码字样。
- 选包阶段仍须先选候选，未进入确认阶段不直接提交；五分钟过期、取消、功能开关、服务可用性及用户/机器人/会话身份检查保留。
- 原幂等键、提交丢失恢复与单任务限制保留；重复消息、运行中再次确认不重复传输。
- 已保存的旧确认流程保留候选、身份、有效期，历史 code 字段不参与判断；新状态预览显示直接确认。已发消息和投递检查点不改写。

验证：构建通过；`node --test tests/firmware*.test.mjs tests/wecom-commands.test.mjs tests/wecom-bridge.test.mjs` 共 65 项通过，零失败/跳过。新增测试覆盖直接确认、包含确认的句子、重复提交隔离、跨用户/群/机器人拒绝、过期/取消拒绝，以及旧带码流程重启后的无代码确认。真实本机 Web API + Bridge 的私聊直接确认、群聊分行提及选包后确认及取消均通过。日志 `.data/firmware-simple-confirm-tests.log` 不提交。

部署需更新主项目、构建并重启 Agent；Bridge 提示同步更新后重启 Bridge。本机下载服务、隧道与环境变量不变。未访问 VPS、未发送真实企微消息、未下载上传真实固件。
