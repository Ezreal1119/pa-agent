# 固件取消指令的不可见字符与群聊提及

截图中“取消 @机器人”仍返回待确认提示。源码确认该提示来自待确认阶段的固定分支：取消要求完整匹配，未清理的提及或不可见字符会导致匹配失败。标准群聊文本在本机可以取消；未读取线上消息原文，具体线上触发字符或 Bridge 版本未作断言。

## 调整

- Bridge 的固件专用文本清理移除 U+200B、U+2060、U+FEFF，兼容词内、词尾、提及内及分行提及之间的常见不可见字符。普通聊天及其他模式继续使用原文本。
- 对完整“取消”或 cancel，允许与当前配置机器人的精确提及直接相邻；不会剥离其他人或前缀相似的显示名。
- 未匹配的尾部取消提及给出明确“取消尚未执行”提示，保留现有流程，管理员可核对显示名配置。引用、附件、NUL、原始长度与正文多行限制继续先行校验。
- 主服务独立容忍完整取消指令中的同一组不可见字符，原有身份、会话、过期、幂等及本机停止确认逻辑保持。包含“取消”的普通句子不会因此被当作取消。

## 验证

构建通过；`node --test tests/firmware*.test.mjs tests/wecom-commands.test.mjs tests/wecom-bridge.test.mjs` 共 73 项通过，零失败或跳过。

新增回归覆盖三种不可见字符、相邻/分行提及、自定义机器人名、未匹配提及、输入边界、重复消息、跨用户/群/机器人隔离、确认前取消零提交，以及执行中等待本机确认停止才释放名额。真实本机 Web API + Bridge 测试复现确认阶段截图场景，验证退出流程并清除 Bridge 输入状态，不产生新下载或上传请求。日志在被忽略的 `.data/firmware-cancel-normalization-tests.log`。

## 生效方式

同步代码后构建，重启主 Agent 与 WeCom Bridge。本机固件服务及隧道不需更新或重启。本轮未访问 VPS、未读取或修改实际环境配置、未发送真实企微消息、未修改生产任务或传输正式固件。线上新消息需在部署后验证。
