# Sync 通知分段排版与简短摘要

- 结果标题、北京时间、概览、各文件独立分段；文件名加粗，保留原下划线。隐藏概览里的零值统计，非零失败/待处理/跳过/未处理仍完整展示。
- 每个文件最多展示两条 72 字以内的原摘要短句，排除内部路径、节点键、索引文件等实现细节和过期的暂存提示；不调用额外模型，不改原始报告，不编造业务变更。技术摘要无法简化时由状态与网页报告提示承接。
- 完成但有失败/待处理使用警示标题；失败、停止和中断保留真实状态。普通业务日期不当作路径删除。
- 个人消息的费用信息单独分段，金额、费用区间及计价完整性说明均保留；群消息继续只发摘要。队列、ACK、费用账本、目标配置与原始同步结果不变。
- 仅新生成通知生效，已冻结/已发送的通知不改写，避免与已投递分片混用。部署时构建并重启 Agent；无需 Bridge、环境变量、定时器或本机固件服务变更。

验证：`npm run build` 与 `node --test tests/sync-notifications.test.mjs` 通过，21 项零失败/跳过。新增覆盖用户截图的实际摘要、路径/节点键过滤、Unicode 路径、业务日期、长摘要和八文件上限、失败/待处理状态以及个人费用信息保留。日志 `.data/sync-notice-layout-tests.log`、示例 `.data/sync-notice-layout-preview.md` 不提交。未访问 VPS、未读写实际 `.env`、未发送真实企微消息。
