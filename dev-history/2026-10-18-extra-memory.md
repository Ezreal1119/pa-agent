# 额外记忆与三个专用工具

用户要求新增全局额外记忆，同时保持两个 Skill MEMORY 不变，并取消 list/get 工具。

- `src/agent/extra-memory.ts` 负责固定路径读取、格式解析、ID/元数据生成、版本检查、同进程队列、备份与原子保存。不存在或空文件允许注入空状态，不自动制造记忆条目。
- `src/tools/memory.ts` 使用 SDK customTools 注册 memory_add/memory_edit/memory_delete。参数只有内容/类别、ID、版本，没有文件路径。用户明确写入意图由模型指引要求；文件范围及版本由后端强制校验。
- Runtime 继续使用四个只读检索工具，增加三个记忆工具，总数七个。两个 Skill MEMORY 不能被这些工具修改；通用文件编辑与 Bash 仍不可用。
- 每轮额外记忆与两份 Skill MEMORY 分开注入，同轮系统快照不变，工具结果可用于本轮后续操作，下一轮读取最新磁盘文件。
- 增加 typebox 1.3.7 的直接依赖。Web 调试显示当前额外文件大小、段注入计数和记忆工具活动；无额外记忆管理网页。
- 41 项本地测试通过，使用真实 SDK + 本地模拟模型测试三个工具端到端。并行冲突、路径限制、Skill ID、格式、备份、取消、链接、恢复和注入均有行为验证。浏览器在 localhost 的隔离测试目录新增一次测试偏好，未写入用户真实文件、未调用真实模型。

实际 `.data/memory/MEMORY.md` 保持用户创建的空文件；两个 Skill MEMORY 未修改。仅对 SKILL.md 补充作用域说明，旧文件备份在 `.data/maintenance-backups/2026-10-18-extra-memory-skill-scope-013834/`。

备份与额外记忆不受 30 天 session 保留策略管理，当前不自动清理；同一记忆文件由一个服务进程负责写入，未实现跨进程锁或 OS 沙箱。

## 后续修正：合并单工具

用户澄清三个是操作种类，合并为单个 `memory`，由 action=add/edit/delete 选择。Runtime 仅激活此名称，合计五个工具。原三个工具名拒绝执行，日志仍能查看；存储逻辑和记忆数据没有迁移。参数按操作验证，并继续要求 expected_revision。

两个运行 SKILL 只修改工具引用，备份在 `.data/maintenance-backups/2026-10-18-single-memory-tool-014510/`。42 项本地测试通过，包括单工具三分支端到端、未知 action、旧工具名和不完整/矛盾参数。未调用真实模型。
