# 2026-10-24：WeCom 欢迎语、角色设置与清空上下文

## 需求与实现

在 ProductExpertCloud 当前分支实现，生产服务不由本次开发自动更新或重启。

- Bridge 使用现有官方 SDK 的 `event.enter_chat` / `replyWelcome` 恢复私聊欢迎语；群聊不发送，事件频率服从企微平台。
- `/role` 和 `/clear` 按消息文本前缀识别，忽略尾随文字；图文混合消息中的命令先于附件下载处理。固定交互不进入模型、不显示 AI Thinking。
- `/role` 显示三个例子和当前原文，记录当前输入者。该输入者的下一条非命令纯文本原样替换设置；空白、附件、引用不作为角色。设置流程中的“取消”保留原设置，“清除”恢复默认；其他群成员照常问答，新的 `/role` 可以接管设置。
- 作用范围沿用 `[botId, chatType, target]`：私聊 target 为 userId，群聊为 chatId。Bridge 只保存命令进度、输入者和范围版本；后端保存角色。
- 新增 `GET/PUT/DELETE /api/wecom/role?scope=<URL编码JSON三元组>`，继续要求本机来源与独立 Bridge Bearer 凭据。PUT 只接收 text，DELETE 接收空对象，GET 返回 text 或 null；不接受任意文件路径。
- 后端 `.data/wecom/roles.json` 按作用范围哈希存储、串行原子写入、0600，校验格式/大小/链接。不会写入主记忆、公共额外记忆或普通聊天历史；清空和会话保留策略不删除角色。
- Core 的 `createSession` 增加可选 `userRoleStyle` 提供器。Web 服务只在经验证的企微运行中按发送者确定角色，每轮冻结；System 在 Extra MEMORY 后追加 `# User Role & Style` 与原文。普通 Web 请求不加载，MCP 文本模式直接忽略提供器。
- `/clear`、旧 `/new` 和“新建对话”停止对应旧运行、取消原排队/待投递任务、解除待处理附件绑定、退出角色输入状态，并创建空白会话。旧记录/附件保留后台归档，沿用闲置三十天清理规则。
- 范围版本拦截迟到模型事件与文件；清空确认等待已发起的投递/进度结束。重复回调沿原消息去重；中断重启恢复命令，角色写入可幂等重试，重置保存旧停止目标和新会话ID。连续清空仍能停止最早的旧任务。后端预览不可用时，“取消”可以结束设置并取消旧提示。

## 验证方法

使用本机 Node v25.6.0、项目已安装的真实 Pi SDK 与本地 HTTP 模型替身，不连接真实机器人或付费模型。

```sh
npm run typecheck
npm run build
node --test --test-concurrency=1 tests/*.test.mjs
```

新增 Bridge 用例验证欢迎语、任意轮次/前缀、三个例子、原文保存、取消/清除、多人群聊接管、用户/群/机器人隔离、重启/去重、满队列与运行中清空、慢附件/投递、连续清空及失败命令恢复。真实后端+Bridge用例检查旧会话可查、新会话messages为空、旧内容不进入实际模型请求、角色位于System尾部、清除后工具继续可用。实际SDK工具循环验证当前轮快照不变、下一轮更新；普通Web无泄漏，MCP不调用角色提供器。

调试时修正了新增测试夹具的content块读取与teardown顺序。首次并行完整检查为391/393，另有既有wecom-import超时用例在并发负载下未生成child-ready文件；未修改导入实现，串行完整检查通过。最终验证数量见本次 Core 累积记录。

## 部署边界

无需增加 npm/Python 依赖、环境变量或 systemd unit。更新代码、构建与测试后先重启 product-expert，再重启 wecom-bridge；两个服务均需更新。新角色文件和 Bridge scopes 缺失时按未设置兼容，不修改已有 Library、业务记忆、历史问答、模型凭据或维护备份。

本轮没有执行生产部署、重启或正式知识维护。真实企微欢迎事件、群消息权限、长连接以及真实模型回答风格仍须上线后验收；本机模拟通过不代替这些验收。
