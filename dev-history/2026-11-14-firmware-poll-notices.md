# 固件进度查询失败提醒

实际任务在上传后的资料库复制阶段持续执行并成功，但单次进度查询异常被直接显示为“固件功能维护中”。查询异常的具体原因此前未写入日志，无法据此确认是超时还是链路错误。

- 沿用原轮询重试，连续 3 次失败才提醒“暂时无法获取固件任务进度，当前任务已保留”，同一次异常只提醒一次。
- 成功查询清零失败次数，仅在之前已经提醒时发送“进度查询已恢复”。失败次数持久化，重启不丢失。
- 记录任务 ID、操作、最近阶段、连续失败次数、耗时、错误类型、HTTP 状态和底层错误码；不输出响应正文、凭据或任意错误消息中的 URL。
- 保留任务身份、幂等提交、取消与结果校验，查询异常不重建或取消任务。

验证：`npm run build`、`node --test tests/firmware*.test.mjs`，49 项通过；覆盖短暂失败、成功后重新计数、跨重启累计、单次提醒和恢复、原任务最终成功、日志诊断字段和凭据保护。

部署时仅需同步主项目、构建并重启 `product-expert.service`。无需修改 Bridge、本机固件服务或隧道。已经生成的旧通知保持原样。本轮仅修改本地代码，未部署、提交或推送。
